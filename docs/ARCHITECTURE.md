# Architecture

Two-layer design: provider-agnostic core + provider-specific adapters.

## Layer 1: Core (provider-agnostic)

### `skills/`
The open standard. Each skill is a directory with a `SKILL.md` file following the [Agent Skills Open Standard](https://agentskills.io/specification). Skills are natively discovered by Claude Code, OpenCode, Cursor, Codex, and 25+ compatible agents.

Skills are organized by category — `git/`, `agents-md/`, `loop/`, `comms/`, `productivity/`, `other/` — for filesystem hygiene. The category is purely organizational; install-time symlinks flatten everything to `~/.claude/skills/almanac/<name>` because Claude Code's skill discovery only scans direct children of the skills root. Names must be unique across the whole tree (validator enforces).

Skills use progressive disclosure:
1. **Metadata** (~100 tokens) — name + description, loaded at startup
2. **Instructions** (<5000 tokens) — SKILL.md body, loaded on activation
3. **Resources** (on demand) — scripts/, references/, assets/

Some skills are adapted from upstream sources ([mattpocock/skills](https://github.com/mattpocock/skills), [contember/agent-canvas](https://github.com/contember/agent-canvas)) and track their upstream via `metadata.upstream-sha` in frontmatter. Run `almanac sync` to check for updates.

Reference material (templates, patterns, guardrails) lives in `skills/<category>/<name>/references/` directories, loaded on demand by the skills that use them. Shared design/domain/interview skills (`codebase-design`, `domain-model`, `grilling`) own reusable vocabulary, decision-record rules, and interview mechanics; consumer skills such as `codebase-improve`, `tdd`, `prd-create`, `grill-me`, and `grill-with-docs` declare `metadata.dependencies` and delegate rather than copying those rules.

## Layer 2: Adapters (provider-specific)

### `providers/claude-code/`
Full local plugin:
- `.claude-plugin/plugin.json` — plugin manifest
- `skills/` — symlink to shared `../../skills`
- `hooks/hooks.json` — lifecycle hooks (SessionStart, Stop)
- `agents/` — extensible directory

### `providers/{opencode,cursor,codex}/`
Setup stubs with symlink instructions for each provider's skill discovery path. Codex also has a first-class installer that links skill directories into `~/.agents/skills/almanac/<name>` for `$skill` invocation and `/skills` browsing.

### Agent instruction files (`AGENTS.md` / `CLAUDE.md`)

In-repo guidance follows the `agents-md-map` convention: `AGENTS.md` is the canonical file, `CLAUDE.md` a symlink to it (`ln -s AGENTS.md CLAUDE.md`). The repo **root** carries project-wide rules; **`lib/AGENTS.md`** points agents at the non-auto-loading `CONTEXT.md` domain model and the loop-engine seam rules (adapters are added as files, never central `case` branches). Separately, **`providers/_shared/AGENTS.md`** is the *distributable* global-config payload the installer links to `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md` — a shipped artifact, not navigation guidance, so it never gets a `CLAUDE.md` sibling.

## CLI (`bin/almanac`)

**Registry-driven dispatcher.** `bin/almanac` resolves `ALMANAC_HOME`, sources `lib/core.sh`, and routes to `cmd/<command>.sh` — a command is valid *iff that file exists* (`almanac_list_commands` globs `cmd/*.sh`, mirroring `almanac_providers`). There is no hard-coded command list anywhere: dispatch, `almanac help`, and `tests/test-cli.sh` all derive from the registry, so adding a command is one new file in `cmd/` with no edit to the dispatcher, the help text, or the docs. The command name is guarded to `^[a-z][a-z-]*$` before it touches the filesystem (path-traversal safe); unknown commands print help to stderr and exit 1. Current commands: install, uninstall, list, update, sync, ralph, harden, converge, hub, doctor, help.

**Command contract** (enforced by `tests/test-cli.sh`). Each `cmd/<name>.sh` is *sourced* into `bin/almanac` (runs under its `set -euo pipefail`; finishes with `exit`, not `return`) and self-describes via three header comments — `# summary:`, `# usage:`, `# group:` (`loops`/`providers`/`maintenance`/`other`). `cmd/help.sh` reads those (`almanac_command_meta`) to **generate** the grouped help, so printed help can never drift from the installed command set. Commands set their own strict mode, source a `lib/` file, route `-h|--help` to stdout (exit 0), guard required option values with `_need_value`, and emit terse `_die` errors (no usage dump) on parse failure. Heavy command logic lives in a `lib/<cmd>-core.sh` so the `cmd/` file stays a parse+dispatch shim.

**Bare `almanac` is TTY-gated**: run interactively (stdin *and* stdout are TTYs) it opens the interactive hub (`cmd/hub.sh`); piped or non-interactive it prints help, so scripts that call bare `almanac` keep working and never block on a menu.

**The almanac launcher (`lib/loop-launcher.sh`).** Interactive run *configuration* is unified in one loop-agnostic launcher, `almanac_loop_launch <loop> [native flags…]`. The launcher itself does **not** branch on loop type — it dispatches the adapter's `launch` verb through the loop-adapter seam, so each loop's flag parsing, prompts, env-export, and runner exec live in its adapter file (`lib/loops/<name>.sh::almanac_loop_<name>_launch`). Adding a 4th loop is a single new file in `lib/loops/`; no central case-statement to keep in sync. What the launcher does still own is what every adapter uses identically: the field collectors (`_almanac_launch_need_provider`/`_choice`/`_positive_int` — pick a provider, resolve a model/effort, validate-and-re-prompt for numeric fields so a stray keystroke is a retry, not a crash) and the summary panel (`almanac_loop_launch_summary` — gum-styled or plain), all routed through the shared `almanac_loop_ui_*` gum-or-plain seam. Each adapter's `launch` verb summarises, confirms, and execs the runner — it never reimplements the run, only its config. The runner exec routes through the same adapter's `exec_argv` verb (`almanac_loop_adapter_call <type> exec_argv …` → `_ALMANAC_LOOP_ARGV`, see the loop-adapter seam below), so no central code hard-codes a loop's runner path: ralph's `…/ralph-loop/scripts/once.sh`/`afk.sh`, harden's `almanac harden <target> --loop`, and converge's `almanac converge --goal …` all live in their adapters. `cmd/ralph.sh`, the ralph skill `ralph.sh` (a thin delegate, so direct `bash ralph.sh` and `almanac ralph` share it), and the hub's New-run flow all route through `almanac_loop_launch`, so the config UX is identical everywhere and has a single source of truth.

`cmd/doctor.sh` reports almanac's **optional-dependency** status so users know what is and isn't styled/available: `gum` (Charm — styles loop dashboards + HITL prompts), `gh` (GitHub issue queues + CI watch), and `jq` (findings parsing). The gum check is the binary-presence helper `almanac_gum_present` (in `lib/core.sh`), distinct from the runtime, TTY-gated `almanac_loop_ui_has_gum` — `doctor` and the installers want "is the binary installed", not "should I style this stream right now". `almanac_report_gum` prints the verdict with an install hint, and both the claude-code and codex installers call it at the end of `almanac install`, so install **and** doctor surface gum's presence/absence. Every optional dep is exactly that — absent, the CLI degrades to plain output, keeping almanac's near-zero-dependency promise.

`cmd/harden.sh` is the first harden-loop CLI surface. It uses `lib/harden-core.sh` to draft a target-specific `rubric.md` under `docs/plans/harden/<target-slug>/` in the caller repo, refusing to overwrite an existing contract. Drafts start with `Status: draft`; after the developer edits the contract, `almanac harden <target> --approve` marks it `Status: approved` and appends an approval timestamp. The approval is a **lock the loop enforces**: once a rubric has been drafted, `almanac_harden_rubric_approved` gates the fan-out, so a bare `almanac harden <target>` refuses (via `_die`) to run reviewers against an unapproved contract — the goalposts can only be set by a deliberate human approve. An explicit ad-hoc run with no rubric at all bypasses the gate and proceeds. The rubric is the **bar**: `almanac_harden_rubric_acceptance` reads the `## Acceptance` criteria back, and `almanac_harden_reviewer_prompt` embeds them so reviewers judge against the contract rather than an implicit standard. The bar grows only by ratified defects — `almanac_harden_rubric_append_criterion` appends a new `- [ ]` criterion under `## Acceptance` append-only (monotonic, visible as a diff) and idempotent (an identical criterion is never re-added). Run with no flags, `almanac harden <target>` fans out one read-only reviewer per configured lens (`almanac_harden_fanout`), passing each reviewer the rubric path so the contract is consumed when present. The lens set comes from `almanac_harden_lenses` — the five PRD lenses (`correctness security perf edge-cases contracts`) by default, overridable at runtime via `HARDEN_LENSES` (comma- or whitespace-separated, no enforced cap). Each lens spawns a background worker through the shared worker orchestration with a `read-only` sandbox, resolving its provider/model/effort via `almanac_harden_role_resolve` (see **Per-role provider config** below) so lenses can mix providers. Reviewers run concurrently and never write to the target; once all finish, the parent aggregates each reviewer's findings into the ledger **sequentially** (so there are no concurrent ledger writers), deduped via `almanac_harden_ledger_record`, and prints each lens's findings (jq parse with an awk fallback). Worker pids are captured via a file rather than command substitution so the backgrounded workers stay children of the launching shell and remain waitable; a failed reviewer is reported and skipped without sinking the round. The **target is free-form** — a path, a PR/branch ref (`PR 47`), or a prose description of what to review; there is no filesystem existence gate, and `almanac_harden_reviewer_prompt` tells each reviewer to locate the relevant code itself (for a PR, inspect its diff). Because a free-form description would slug into an unwieldy committed plan path, `almanac_harden_slug` caps the slug at a word boundary (override via `ALMANAC_HARDEN_SLUG_MAXLEN`); both `almanac_harden_rubric_path` and `almanac_harden_ledger_path` route through it so the rubric and ledger always agree on `docs/plans/harden/<slug>/`, while the run registry keeps the full timestamped run-id for disambiguation.

The rubric is **immutable to agents during a run** — the goalposts move only by a deliberate human act (editing/approving the file between runs) or the conductor's controlled append at ratification (`almanac_harden_rubric_append_criterion`, which runs outside the reviewer/fixer phase). The fan-out brackets the reviewer round with an integrity guard: `almanac_harden_rubric_snapshot` copies the rubric before any reviewer spawns and `almanac_harden_rubric_verify` checks it byte-for-byte once they finish, reverting and warning if it changed. Reviewers run read-only and cannot write the rubric, so this is defense-in-depth today; it becomes load-bearing for the write-capable fixer slice, which brackets its own agent call the same way (snapshot after ratification's legitimate appends, revert any fixer edit). An ad-hoc bare run with no drafted rubric has nothing to guard, so the snapshot returns cleanly and the guard is skipped.

The **findings ledger** persists adjudicated findings append-only to `findings.md` beside the rubric. The canonical finding schema is `lens, severity, location, claim, demonstration`; the ledger adds `id`, `status` (`open` | `fixed` | `rejected-subjective` | `wontfix-per-context`), `round`, and an `adjudication` note. `almanac_harden_parse_findings` normalizes a reviewer's JSON-Lines result into ledger-entry rows (new findings are `open`), dropping malformed lines cleanly. `id` is a `cksum` fingerprint of `(lens, location, claim)` — demonstration is excluded so a reworded repro is not a new finding — and `almanac_harden_ledger_record` dedupes against it, so a finding already adjudicated in a prior round is never re-added. `almanac_harden_ledger_open_blocking` reads the ledger back and returns only `status: open` findings, since fixed and rejected findings never gate the loop.

The **ratification engine** decides blocking vs. note by *executing* a finding's demonstration, never by trusting a reviewer's assertion. `almanac_harden_ratify` runs the demonstration through the execution seam `almanac_harden_demo_reproduces` — the **real ratify-by-execution executor** (PRD story 8): it builds a conductor prompt (`almanac_harden_ratify_prompt`) that tells the conductor to carry out the demonstration against the current code and end with a single machine token, runs it through the resolved conductor `(provider, model, effort)` via the shared agent runner (`workspace-write`, like the fixer, since judging by execution means actually running the proposed test/input), and reads the verdict back with `almanac_harden_ratify_verdict` (the affirmative literal `HARDEN_VERDICT=reproduces`; the negative cannot match it). It is conservative on every uncertainty — an empty demonstration, an unresolved provider, a crashed/un-runnable conductor call, or an un-parseable verdict all read as non-reproducing (a note) so opinions never silently gate the loop and a flaky provider never blocks a run. Tests drive the decision paths behind a fake provider (no real model calls). `almanac_harden_ratify` records the outcome in the ledger, printing one verdict: a new/open finding that reproduces → `blocking` (`status: open`); one that does not → `note` (`status: rejected-subjective`); an already-adjudicated finding (`fixed` / `rejected-subjective` / `wontfix-per-context`) that *newly* reproduces → `reopened` (back to `status: open`); one that still does not reproduce → `dropped` (left untouched, never re-litigated). Status transitions go through `almanac_harden_ledger_set_status` (rewrites status + adjudication in place); `almanac_harden_ledger_status` reads a finding's current status so new findings are told from already-adjudicated ones. When `almanac_harden_ratify` is given a rubric path, a finding that reproduces (`blocking` or `reopened`) also appends a falsifiable criterion to the rubric's `## Acceptance` via `almanac_harden_rubric_append_criterion`, so the bar grows monotonically with every ratified defect; notes and drops never touch the rubric, so opinions cannot raise it.

The **single sequential fixer** (`almanac harden <target> --fix` → `almanac_harden_fix`) applies the open blocking findings. v1 is deliberately one write-capable agent — `sandbox=workspace-write` (never read-only), run in place with **no worktree** — so there are never concurrent writers to reconcile and any regression test it generates simply persists in the working tree (PRD: "the deliverable is hardened code *plus the regression suite the loop built to prove it*"). It reads the kill-list from `almanac_harden_ledger_open_blocking`, renders it into `almanac_harden_fixer_prompt` (which also embeds the rubric bar and tells the fixer to leave a failing-then-passing regression test per finding), and runs the fixer through the shared agent runner. The fixer's agent call is bracketed by the same rubric immutability guard the fan-out uses (`almanac_harden_rubric_snapshot` before, `almanac_harden_rubric_verify` after) — load-bearing here because the fixer *can* write the rubric; legitimate rubric growth happens earlier in ratification, outside this bracket. On a clean fixer exit every open blocking finding is marked `fixed` in the ledger (a still-broken one is reopened next round by reviewers/ratify, so nothing is silently closed); a fixer failure leaves the findings open and returns the provider's exit code. With no open blocking findings the fixer is a no-op (spawns no agent). The objective feedback gate is **decoupled** from the fixer so it can run once per round even when there is nothing to fix: `almanac_harden_report_feedback` runs the shared runner and prints a pass/fail verdict per loop. The convergence loop calls it after the fixer (and reads its aggregate as the round's exit code); the standalone `--fix` CLI path runs it right after the fixer so its output is unchanged. **Per-round commit:** when the target is a git work tree, `almanac_harden_round` ends with `almanac_harden_commit_round`, which stages the whole tree **minus `.almanac/`** (the runtime registry — run state, worker dirs, events must never land in the target repo's history) and commits the round's fixer edits + regenerated tests + findings ledger as `harden(<slug>): round N fixes (C)` — the message is composed **by the loop** from the round's kill-list (subject carries the fix count; body lists each addressed finding as `- [lens] claim`; an empty kill-list yields a `… round N checkpoint` commit), so the descriptive message costs nothing in agent trust: the fixer is never handed git and stays in `workspace-write`. It is **unconditional on the feedback verdict** ("commit every round" — a still-red round is still committed, so each round is a reviewable checkpoint; round N+1's reviewers re-surface anything still broken). It no-ops outside a git work tree, when nothing outside `.almanac/` changed, or when `HARDEN_AUTOCOMMIT` is disabled; a commit failure (e.g. no git identity) warns and leaves the changes in the tree rather than aborting the loop. The standalone `--fix` path does **not** commit — only the loop's rounds do.

The **convergence loop** (`almanac harden <target> --loop` → `almanac_harden_run`) repeats hardening rounds until the target is bulletproof or the round budget is hit. One round (`almanac_harden_round`) runs **fan-out → ratify → fix → feedback** in sequence, threading the round number; its exit code is the feedback verdict (0 = all loops green). `almanac_harden_ratify_open` adjudicates every open finding the fan-out recorded by executing its demonstration through the seam (reproducing → stays blocking and grows the rubric bar; otherwise → non-blocking note); that rubric append is the conductor's sanctioned growth and runs *between* fan-out and fix, outside the immutability brackets those phases use. After each round `almanac_harden_run` prints the **kill-list** (the blocking findings still open) and a **verdict**. The verdict comes from the **convergence gate** `almanac_harden_gate_verdict` — a pure predicate over `(acceptance_met, open_blocking, round, budget)` with no I/O, unit-tested across its whole input space: it returns `converged` (exit 0) when acceptance is met **and** zero open blocking findings remain, `non-converged` (exit 2) when the budget is reached without convergence, and `continue` (exit 1) otherwise. Convergence is checked first, so a round that converges exactly at the budget is never mislabelled, and the gate never returns `continue` once the budget is reached, so the loop always terminates. Acceptance for the gate combines the round's feedback verdict with `almanac_harden_acceptance_met` (no unchecked `- [ ]` criteria left in the rubric's `## Acceptance`; vacuously met for an ad-hoc run with no rubric). The budget is configurable via `--rounds N` (default 5, or `HARDEN_ROUND_BUDGET`). On a `continue` verdict the loop pauses at a **HITL checkpoint** (`almanac_harden_hitl_checkpoint`) offering three choices: `HARDEN_HITL` (`ship`|`continue`|`steer`) drives it non-interactively, a TTY prompts via `gum choose`/`gum input` when present and a plain `read` otherwise, and an unattended run defaults to continue. **Ship** stops the loop and accepts the current state; **continue** runs another round; **steer** captures a directive (from `HARDEN_STEER` or the prompt, echoed on the checkpoint's stdout with the return code `2`) that `almanac_harden_run` carries forward and threads — via `almanac_harden_round` → `almanac_harden_fanout`/`almanac_harden_fix` → the reviewer and fixer prompts — into every subsequent round, so the operator can redirect or amend the run between rounds without babysitting each worker (PRD story 18). The directive persists until steered again; a rubric amendment is also picked up between rounds, since the fan-out re-reads and re-snapshots `rubric.md` each round.

`cmd/converge.sh` is the generic loop sibling to ralph and harden. It launches with `almanac converge --goal <goal> (--prompt <text>|--exec <cmd>) [--rounds N] [--no-oversee] [--oversee-every N]`, stores canonical state under `docs/plans/converge/<slug>/`, registers `type=converge` in the shared run registry, and can later render status, watch, or stop via `almanac converge <slug> [--watch|--stop]`. `lib/converge-core.sh` owns the whole converge lifecycle: slug/scaffold, worker prompt and editable `prompt.md`, read-only overseer prompt, conservative four-field verdict parse, one-shot `.converge-steer`, `.converge-stop`, direct `goal.md` mutation with `goal.history.log`, final `convergence.md`, dashboard frame, and EXIT-trap-safe run finalization. Unlike ralph's PRD queue or harden's lens fan-out, converge runs exactly one user-supplied action per round; convergence is an overseer judgment against the current mutable goal. The worker and overseer both use `lib/agent.sh`, `lib/role.sh`, and `lib/run.sh` directly, so converge is a first-class shared-engine consumer rather than a fork.

**Per-role provider config.** Every harden role selects its own `(provider, model, effort)` through `almanac_harden_role_resolve <role> [lens]` — one tab-separated `provider<TAB>model<TAB>effort` line so callers populate three locals with a single `IFS=$'\t' read` — the one place harden's per-role defaults live. The three roles are **conductor** (judges/ratifies), **reviewer** (one per lens), and **fixer** (the single sequential writer). It layers over the shared loop resolver, most specific first: `HARDEN_<ROLE>[_<LENS>]_{PROVIDER,MODEL,EFFORT}` → `HARDEN_<ROLE>_*` → `HARDEN_*` → harden's default (provider `claude`; the provider's own default model/effort). Only reviewers consult the lens, so providers can be **mixed across lenses** in one round; conductor and fixer ignore it. Resolution reads only `HARDEN_*` env — never any host marker — so the tuple is identical whether the run was launched from Claude Code or Codex. The fan-out resolves each reviewer per lens and the fixer resolves its own; the convergence loop announces the resolved conductor at start and hands its identity to the execution seam (`almanac_harden_demo_reproduces`, via `almanac_harden_ratify`) for every ratified finding, so the provider that *judges* findings — by actually executing each demonstration through the agent runner — is the configured conductor, mixable per role and independent of the launching host.

Converge roles use the same resolver with a `CONVERGE_` prefix: `CONVERGE_AGENT_{PROVIDER,MODEL,EFFORT}` controls the write-capable worker, `CONVERGE_OVERSEER_{PROVIDER,MODEL,EFFORT}` controls the read-only overseer, and `CONVERGE_{PROVIDER,MODEL,EFFORT}` is the consumer-wide fallback. Adding another loop consumer should mirror this pattern: define role names, document the env prefix, route calls through `almanac_loop_role_field` (single field) or `almanac_loop_role_resolve` (all three at once), and keep provider defaults out of command parsing.

**Supervision dashboard.** A run is supervised through a `gum`-styled redraw dashboard composed from live run state: reviewer status (per lens, with health), the round, findings tallies, rubric progress, and the feedback verdict. Following the PRD's "render logic is pure" rule, the composer `almanac_harden_dashboard_rows` is a **pure function** — it reads worker rows from stdin as `id<TAB>provider<TAB>health` TSV and takes the round/budget, findings tally, rubric progress, and feedback verdict as args, returning the printable rows with no file I/O, clock, or terminal, so it is unit-tested across all five fields without a terminal. The gather helpers feed it real state: `almanac_harden_dashboard_worker_rows` reads each worker's `status.tsv` and classifies its health via the shared detector; `almanac_harden_findings_tally` counts the ledger by status (`open=N fixed=N notes=N`, where notes = `rejected-subjective` + `wontfix-per-context`); `almanac_harden_rubric_progress` reports `checked/total` over the `## Acceptance` checklist; and `almanac_loop_latest_run_for_target` (in `lib/run.sh`) locates the target's most recent run by registry append order — one generic helper both harden and converge dispatch through with a type literal, replacing two divergent per-loop wrappers that disagreed in mechanism (glob+mtime vs row-scan) but agreed in intent. `almanac_harden_render_dashboard` ties these together and wraps the composed rows in `almanac_loop_ui_render`, which styles them as a rounded `gum` panel on a TTY and **degrades to plain passthrough** when `gum` is absent (or `ALMANAC_NO_GUM=1`, or output is piped) — keeping almanac's near-zero-dependency promise. It is safe to call before any run/worker/rubric state exists: it degrades to an empty reviewer list and zeroed tallies rather than failing.

The dashboard is **watched live** through `almanac_harden_dashboard_redraw` (the `almanac harden <target> --watch` mode and the hub's "watch a run" action): a redraw loop that, each frame, clears the terminal (TTY only, via the shared `almanac_loop_ui_clear` — never polluting piped output) and reprints `almanac_harden_render_dashboard` from the run's live worker/ledger/rubric state, so reviewer health, findings tallies, rubric progress, and the verdict update as the run progresses. Termination is bounded by construction so it can never run forever: a positive frame cap renders exactly that many frames (the unit-test path); off a TTY an uncapped call renders a single frame and returns (so a pipe/script never blocks); on a TTY it redraws until the latest run's workers have all finished (`almanac_harden_run_has_active_worker`, which keys on each round's per-worker `status.tsv` for liveness — the loop-level run-status blob tracks round/verdict) or there is no run to watch. A single worker's live event stream is watched through `almanac_harden_watch_worker` (`--watch-worker <lens|worker-id>`), which resolves the target's most recent run, accepts a bare lens as shorthand for its `reviewer-<lens>` worker, and delegates to the shared `almanac_loop_worker_watch` — tailing the worker's `events.jsonl` live (`tail -f`) on a TTY and printing its current contents once otherwise. The **steer flow** completes the supervision half: the HITL checkpoint's `steer` choice (above) lets the operator redirect or amend a run between rounds, threading a directive into the subsequent rounds' agents.

**Interactive hub.** Bare `almanac` in a TTY (and `almanac hub` always) opens the **hub** (`cmd/hub.sh`) — the front door to every loop, built as a thin reader over the run registry rather than a retrofit. Its read views are **pure registry projections** so they are testable off a terminal and degrade to plain text without gum. `almanac_loop_hub_render <root> <which> [limit]` projects the registry into one of two lists: `running` emits every run whose lifecycle status is still `running`, carrying its live `round`/`summary` from the run-status blob, and surfaces a running entry whose pid is gone as `stale` (via `almanac_loop_run_is_stale`) so a crashed run is visible rather than silently lost; `recent` emits the finished runs (done/failed/aborted) newest-finish-first, capped at `limit` (default 10). `almanac_loop_hub_overview` composes both sections (with empty-state lines) and frames them through the shared `almanac_loop_ui_render`, so the hub shows a rounded gum panel on a TTY and plain text without gum. Off a TTY `cmd/hub.sh` renders that overview once and exits — it never blocks on a menu, so `almanac hub | cat`, scripts, and tests get a clean read view (`tests/test-hub.sh` drives the real `bin/almanac` chain: bare-almanac-off-a-TTY prints help and does *not* open the hub; `almanac hub` renders the running + recent overview from a seeded registry). The **per-run actions** layer on this read view: selecting a running loop offers **watch**, **stop**, and **queue-steer**, each a pure-ish file/signal operation in `lib/run.sh` so it is unit-testable and also drivable non-interactively (`almanac hub --watch|--stop|--steer <id>`, the seam the gum menu and scripts/tests share). `almanac_loop_signal_file <type> <kind>` (in `lib/loops.sh`) maps a run type to the dot-file its runner watches between rounds (`.ralph-stop`/`.ralph-steer`, `.harden-stop`/`.harden-steer`, `.converge-stop`/`.converge-steer`) — it dispatches to the loop adapter's `signal_file` control verb (see the loop-adapter seam below) rather than branching on type, so each loop owns its own signal files. `almanac_loop_run_stop` writes that stop file under the run's root (its working dir) **and** best-effort `TERM`s a live numeric pid (never a dead/finished one), so a run tears down at its next between-round check or immediately if blocked mid-round. `almanac_loop_run_steer` writes the directive to the steer file the next round consumes (each loop consumes its own steer file), rejecting a blank directive. `almanac_loop_run_detail` is the pure per-run detail render (identity, live status — upgraded to `stale` when a running pid is gone — round/summary, start/finish); `almanac_loop_run_watch` renders it once off a TTY (the scripts-safe path) and redraws it on a `follow` TTY until the run reaches a terminal status. On a TTY, `cmd/hub.sh`'s `almanac_hub_menu` opens a selection menu whose top entry is always **+ New run**, followed by each running loop (each row carries `[id]`) and `quit`; selecting a running loop opens a watch/stop/steer/back action menu over it. The menu opens even with an empty registry (so New run is reachable with no prior runs), and **degrades gracefully without gum**: with gum it is a styled `gum choose`/`gum input`/`gum confirm`, and without gum it renders as a plain numbered menu read over stdin — both built on the shared `almanac_loop_ui_choose`/`almanac_loop_ui_input`/`almanac_loop_ui_confirm` seam, so the same menus work on any TTY. Off a TTY (piped/captured) the hub still renders the read-only overview once and exits. The **new-run** flow is itself built on a pure composer + non-interactive seam, mirroring the per-run actions: `almanac_loop_new_run_argv <type> [key=value…]` composes the launcher argv (one token per line, leading with the loop subcommand) — ralph config maps to ralph.sh flags (`--prd`/`--mode`/`--provider`/`--model`/`--effort`/`--iterations`/`--no-oversee`), harden launches the convergence loop (`harden <target> --loop [--rounds N]`), and converge launches either prompt or exec mode (`converge --goal ... --prompt|--exec ...`); `almanac_loop_new_run_env <type> [key=value…]` composes the `KEY=VALUE` env a run needs beyond its argv (ralph emits none — all flags; harden's reviewer config rides on `HARDEN_LENSES`/`HARDEN_PROVIDER`/`HARDEN_MODEL`/`HARDEN_EFFORT`; converge's role config rides on `CONVERGE_PROVIDER`/`CONVERGE_MODEL`/`CONVERGE_EFFORT`). Both return 1 for an unknown type and 2 for a missing required field (ralph: prd; harden: target; converge: goal plus exactly one of prompt/exec), so a malformed run is rejected rather than launched. `cmd/hub.sh`'s `almanac_hub_launch_new` either prints the resolved `ENV… almanac <argv>` command (dry-run, the scripts-safe preview the gum confirm reuses) or exports the env and execs the launcher, handing over the terminal. The interactive New-run flow (`almanac_hub_new_run`) picks the loop type, then hands off to the shared **almanac launcher** (`almanac_loop_launch`, see the CLI section) — no run-config logic lives in the hub any more; the same launcher backs direct loop CLIs, so the New-run UX is identical to running those directly. (The non-interactive `--new` composer seam below stays for scripts/tests.) The seam is also drivable directly: `almanac hub --new <ralph|harden|converge> [config…] [--dry-run]`. `tests/test-hub.sh` pins the non-interactive seams (`--steer` writes the steer file with the directive, `--stop` writes the stop file, `--watch` renders the run detail once off a TTY, `--new … --dry-run` composes ralph, harden, and converge launches and rejects a run missing its required config). The argv/env composers themselves do **not** branch on loop type — each loop adapter implements `new_run_argv` / `new_run_env` / `new_run_usage` as additional contract verbs (alongside `launch` / `launch_usage` / `exec_argv`), and `almanac_loop_new_run_argv` / `_env` in `lib/run.sh` are thin dispatchers that validate the loop name (`almanac_loop_adapter_known` → 1 for unknown) and forward the key=value stream through `almanac_loop_adapter_call`. Adding a 4th loop adds the composer verbs to its adapter; the dispatcher does not change.

The `harden-loop` skill (`skills/loop/harden-loop/SKILL.md`) is the agent-facing companion to the harden CLI - it teaches the convergence contract, the round structure, lenses, per-role provider config, supervision, and gum-optional degradation, pointing at `almanac harden <target>`. The `converge-loop` skill (`skills/loop/converge-loop/SKILL.md`) is the companion to `almanac converge` - it teaches the generic goal/prompt-or-exec loop, mutable goal state, overseer contract, role config, supervision, and when to choose converge instead of ralph or harden. Like `ralph-loop`, both are `disable-model-invocation: true` heavyweight autonomous loops: user-invocable via `/almanac:harden-loop` or `/almanac:converge-loop`, and loadable by orchestrators without bloating the auto-listing.

## Shared Loop Engine (`lib/run.sh`, `lib/worker.sh` + focused modules)

The loop behavior Ralph, harden-loop, and converge-loop build on is split across **focused modules**, each its own test surface — the old `lib/loop-core.sh` god-module was **deleted** (loop-engine-split slice 09), not kept as a barrel, and every caller sources only the modules it uses. `lib/run.sh` owns the run registry + run-status record + control (stop/steer/watch) + worker health + the hub's read views; `lib/worker.sh` owns the worker orchestration (background fan-out); the UI seam, role config, agent shapes, provider/loop adapters, and feedback each live in their own file (below). The **feedback engine** lives in its own module, **`lib/feedback.sh`** (extracted from the engine in loop-engine-split slice 07): feedback detection (`almanac_loop_feedback_commands`) maps project marker files to commands and renders prompt-ready markdown (`almanac_loop_feedback_markdown`); the **feedback runner** (`almanac_loop_feedback_run`) is its execution half — it runs each detected loop from the project root, emits one `<command>\t<pass|fail>` verdict row per loop, and returns a non-zero aggregate when any loop failed, so a caller can gate on the aggregate while reading per-loop verdicts. `lib/feedback.sh` is self-contained (no `lib/core.sh` dependency — only printf/tr/mkdir/eval) and its own test surface (`tests/test-feedback.sh`: the marker-file→command mapping and the per-loop verdict + aggregate exit code). The engine modules do not use feedback internally; its consumers source `lib/feedback.sh` **directly** — Ralph's `prompt.sh` for the detection markdown (its only engine dependency), and `lib/harden-core.sh`'s fixer gate (`almanac_harden_report_feedback`) for the runner — rather than borrowing it transitively. Role config resolution lives in its own module, **`lib/role.sh`** (extracted from the engine in loop-engine-split slice 06): `almanac_loop_role_field` layers lens-specific, role-specific, consumer-wide, then default provider/model/effort values, so harden reviewer lenses can mix providers, and `almanac_loop_role_resolve` projects a role's full tuple as one tab-separated `provider<TAB>model<TAB>effort` line so a caller pulls three locals in one read. `lib/role.sh` is self-contained (no `lib/core.sh` dependency — only printf/tr/sed + bash indirect expansion) and its own test surface (`tests/test-role.sh`: the lens→role→consumer-wide→default precedence, the set-empty-wins rule, env-key normalisation, and the one-line role_resolve projection). The engine modules do not use role config internally; its consumers source `lib/role.sh` **directly** (`once.sh`/`afk.sh` for the iteration agent, `lib/harden-core.sh` for its three roles, `lib/converge-core.sh` for its agent and overseer roles) rather than borrowing it transitively. **Ralph resolves its iteration-agent provider/model/effort through this same shared helper** (`once.sh` and `afk.sh` call `almanac_loop_role_field ralph agent …`): the bare `RALPH_PROVIDER` / `RALPH_MODEL` / `RALPH_EFFORT` still work as the consumer-wide fallback, and new per-role `RALPH_AGENT_*` keys now override them. Provider config still falls through to ralph's own CLI auto-detection (`CODEX_THREAD_ID`, then the installed CLI) when no key is set — that runtime detection is ralph-specific, not a role-config concern. afk's overseer reuses the iteration agent's role-resolved model/effort (as before), now passed straight to the shared seam (a non-stream, read-only call) rather than shaped into local arg arrays. The shared **agent run shapes** live in `lib/agent.sh` (moved out of `loop-core.sh` in loop-engine-split slice 04) as three intention-revealing functions that replace the old mode-parametric `agent_run`: each takes the common quartet `(provider, model, effort, sandbox)` plus a prompt file and a result file, consumes the provider adapter's argv + filter, and owns only execution mechanics — so a call reads as intent and there are no invalid mode combinations to guard. **`almanac_loop_agent_capture`** runs the provider silently, capturing the raw event stream to its events file and (for adapters with an `*_extract` hook) the final result to the result file via a direct redirect that keeps the provider's exit; harden's fan-out / ratify / fixer, ralph's overseer, and converge's worker/overseer calls use it. **`almanac_loop_agent_stream`** additionally tees that raw stream to the events file *and* pipes the adapter's filtered live assistant text to stdout, preserving the producer's exit across the tee/jq pipe via `PIPESTATUS` (a provider failure still propagates instead of being masked by the filter) and never echoing the events-file path (it would corrupt the live stream); an optional trailing **merge-stderr** flag folds the provider's stderr into the captured/streamed output (`2>&1`) so a caller that relies on stderr-in-log — ralph `once.sh`'s `codex ... 2>&1 | tee` — keeps that capture, default leaving stderr on the terminal. **`almanac_loop_agent_raw`** is the native-passthrough shape for adapters that declare `*_supports_raw` (codex): it runs *without* `--json` so codex's native output streams straight to the terminal (no jq filter, no events capture), while `--output-last-message` still captures the result and the direct exec propagates codex's exit — ralph's `RALPH_CODEX_VERBOSE` mode; a provider without raw support degrades to a silent capture so output is never dropped. Each shape is its own test surface in `tests/test-agent.sh` (per-shape behavior behind a fake provider — argv shaping, the sandbox→permission mapping, stream filtering, `PIPESTATUS` propagation, and the raw/degrade paths). The routing has landed for **both `once.sh` providers**: its **claude** invocation runs through `almanac_loop_agent_stream`, and its **default codex** invocation now does too (stream + merge-stderr, so the session log still captures the raw `--json` stream *and* codex's stderr) — neither is an inline provider exec any more, and both gain the seam's `PIPESTATUS` failure propagation (the claude path also gained a real failure surface, since its old pipe had no `pipefail`). `once.sh`'s `RALPH_CODEX_VERBOSE` raw-output branch now routes through the seam too, via its **raw** passthrough mode (no `--json`, native output to the terminal); the result-print and failure-tail are thin ralph post-steps around the seam call. With both providers and the verbose branch routed, `once.sh` no longer builds `MODEL_ARG`/`EFFORT_ARG` arrays or runs any inline provider exec — that arg-shaping lives in the seam. The same routing has now landed for `afk.sh`'s **default codex** invocation: it runs through `almanac_loop_agent_stream` in merge-stderr mode (so the per-iteration session log still captures the raw `--json` stream *and* codex's stderr), the seam's `--output-last-message` target is afk's `$tmpfile` so the `<promise>` extraction reads the result back unchanged. `afk.sh`'s **claude** invocation now routes too: the seam gained a **permission-mode opt-out** — a `default` sandbox sentinel makes `almanac_loop_agent_claude_permission` return an empty mode so `--permission-mode` is omitted entirely (claude's own default), preserving afk's iteration agent, which (unlike `once.sh`, which uses `acceptEdits`) has never set one. afk passes its `$tmpfile` as the seam's result file and reads the extracted result back for `<promise>` extraction (as its codex path does), and gains the seam's `PIPESTATUS` failure propagation — its old inline pipe had no `pipefail`, so claude failures were swallowed and the run was falsely marked done. With this, **every ralph provider invocation — both iteration providers in both `once.sh` and `afk.sh`, each script's `RALPH_CODEX_VERBOSE` raw-output branch, AND afk's overseer read-only judge call — now routes through the shared seam** (via its raw passthrough mode for the verbose branches): **no inline provider exec remains in either launcher (#66 criterion 6)**. The overseer's call is a **non-stream** seam call with the `read-only` sandbox (→ claude `--permission-mode plan` / codex `--sandbox read-only`, the read-only modes it used inline) — the overseer parses the verdict rather than streaming it, so the seam captures the model's response to a result file the overseer reads back; it reuses the iteration agent's role-resolved `AGENT_MODEL`/`AGENT_EFFORT` (its model/effort today) and is guarded with `|| true` so a flaky/missing provider can never kill the overseer subshell. With the overseer routed, `afk.sh` has dropped its `MODEL_ARG`/`EFFORT_ARG` arrays too, reaching parity with `once.sh` — provider arg-shaping now lives only in the seam. The migrated `almanac ralph` is verified end-to-end by `tests/test-ralph-smoke.sh`, which drives the full user-facing chain (`bin/almanac` → `cmd/ralph.sh` → the launcher → `once.sh`/`afk.sh`) behind a fake provider — asserting a once run registers and completes, afk honors the iteration budget, afk stops on the agent's `<promise>COMPLETE</promise>`, the overseer is wired on by default (off with `--no-oversee`), and afk pushes the agent's commit to the remote at end-of-loop — so the loop's iteration, commit, and overseer behavior are unchanged by the migration (#66 criterion 5). **#66 (ralph migration onto the shared engine) is complete.** Worker orchestration (`lib/worker.sh`) starts provider runs in the background through that runner and records per-worker `status.tsv`, `events.jsonl`, `result.txt`, and `stderr.log` files under the run directory. The run registry records launched loops under `.almanac/runs/` in the caller repo so multiple runs (harden, ralph, converge) can be listed and monitored from one place. `index.tsv` is the lightweight list pointer — id/type/target/pid/status-file/start/status, one row per run — and each run also gets a `status.tsv` **blob** that is the per-run detail view. The blob carries the same identity plus the live progress the index does not: `round` (harden round / ralph iteration / converge tick) and `summary` (a worker/lens/goal summary line), updated mid-run via `almanac_loop_update_run_progress`. On exit a run is marked `done`, `failed`, or `aborted` with a finish time (`almanac_loop_mark_run_status`); a still-`running` entry whose pid is gone is detectable as stale via `almanac_loop_run_is_stale` (so a crashed run can be surfaced/reaped). The hub-facing read API is `almanac_loop_list_runs` (all index rows, header stripped) and `almanac_loop_read_run` (one run's full blob). The blob is the **run-status record**, and its schema is the **single run-status contract** — identical for harden, ralph, and converge **by construction**. The record module **`lib/run.sh`** (extracted in loop-engine-split slice 05) owns the canonical field list (`id`, `type`, `target`, `pid`, `status_file`, `started_at`, `status`, `finished_at`, `round`, `summary`) in one place — `almanac_loop_record_fields` — and exposes set/get-by-name accessors: `almanac_loop_record_get <file> <field>` reads a field, and `almanac_loop_record_set <file> field=value…` rewrites the record with the full canonical key set, preserving every field a caller does not name (and rejecting a non-canonical field). So `register` seeds the record by naming only its launch fields, `mark`/`update` change only their lifecycle/progress fields, and **no caller enumerates the schema** — the identical-key-set guarantee is structural, not asserted after the fact (the index row remains the lightweight pointer: the record's first seven fields, `id`/`type`/`target`/`pid`/`status_file`/`started_at`/`status`). `lib/run.sh` is self-contained (no `lib/core.sh` dependency) and its own test surface (`tests/test-run.sh`: schema, set/get-by-name, round-trip-preserving write, unknown-field rejection, and the identical-key-set-by-construction contract); `almanac_loop_status_field` is now a thin alias over `almanac_loop_record_get` (both in `lib/run.sh`). `ralph-loop` launchers source `ralph-run-registry.sh`; `once.sh` and `afk.sh` register the PRD run before starting providers, call `ralph_update_run_progress` (a guarded wrapper over `almanac_loop_update_run_progress`) at the start of each iteration to emit the live `round` (iteration number) + `summary`, and mark it at process exit — so a running ralph shows live iteration progress in the hub through the same run-status contract harden emits, not just a start/finish marker. On the harden side, `almanac_harden_run` registers the loop-level run at start (`type=harden`), calls `almanac_loop_update_run_progress` each round (round + lens/open-blocking summary), and finalizes it through `almanac_loop_run_finalize` — `done` on converge or ship, `failed` at the round budget, `aborted` on a signal or mid-round `_die` (via an `EXIT`/`INT`/`TERM` trap) — so a harden run appears in the hub with the same lifecycle as ralph. On the converge side, `almanac_converge_run` registers `type=converge`, updates round progress as `goal=<slug>`, and finalizes done/failed/aborted through the same registry contract. `.almanac/` is ignored because registry state is runtime-only.

The **gum-or-plain UI seam** every consumer's dashboard composes from lives in its own module, **`lib/ui.sh`** — extracted from the engine (loop-engine-split slice 02) so each consumer (`lib/loop-launcher.sh`, `lib/harden-core.sh`, `cmd/hub.sh`, and `lib/run.sh` for the hub read views) sources it **directly** rather than borrowing it transitively; `lib/ui.sh` is self-contained (no dependency on `lib/core.sh`) and is its own test surface (`tests/test-ui.sh`). `almanac_loop_ui_has_gum` is the single gate for `gum` styling — true only when `gum` is installed, stdout is a TTY, and `ALMANAC_NO_GUM` is unset — so styled output is opt-out and never appears in piped/captured streams; `almanac_loop_ui_render` styles a stdin block as a rounded panel when that gate is open and passes it through unchanged otherwise (graceful degradation); `almanac_loop_ui_status_glyph` is a pure state→glyph map; and `almanac_loop_ui_clear` clears the terminal between redraw-loop frames only when stdout is a TTY (a no-op off a terminal, so it never pollutes piped/captured output). It also owns the **interactive selection primitives** the hub menus are built on — `almanac_loop_ui_choose` (pick one of N options), `almanac_loop_ui_input` (free-text value with optional default), and `almanac_loop_ui_confirm` (yes/no) — each gum-styled (`gum choose`/`gum input`/`gum confirm`) when `almanac_loop_ui_has_gum` is open and degrading to a plain numbered menu / `read` prompt otherwise, so menu-driven flows work on any TTY without gum. The selection *logic* is split into pure, unit-tested helpers — `almanac_loop_ui_menu_render` (options → numbered list) and `almanac_loop_ui_menu_pick` (typed number → chosen option, rejecting blank/non-numeric/out-of-range) — with the choose/input/confirm wrappers adding only the gum-or-`read` I/O around them; the prompt goes to stderr so callers capture only the choice on stdout. `lib/worker.sh` also owns `almanac_loop_worker_watch`, which streams one worker's live `events.jsonl` so any consumer can watch a single reviewer/fixer — reading the worker's events-file path from its `status.tsv`, tailing it live (`tail -f`) on a TTY and printing its current contents once otherwise (so pipes and tests never block). **Worker health detection** (`lib/run.sh`) classifies a reviewer's progress so the dashboard can surface a stalled (log stopped advancing), idle (running but never produced an event), or looping (same event repeating) worker: `almanac_loop_worker_health` is a pure predicate over `(status, log-age, event-count, trailing-repeat, stall-threshold, loop-threshold) → running|stalled|idle|looping|done|failed` (table-tested with no files/clock), fed by the gather wrapper `almanac_loop_worker_health_of` (with `almanac_loop_file_age_secs`, `almanac_loop_count_lines`, and `almanac_loop_trailing_repeat` measuring the worker's `events.jsonl`).

The **provider-adapter seam** every consumer's provider knowledge routes through lives in **`lib/agent.sh`** + **`lib/providers/<name>.sh`** — extracted from the engine (loop-engine-split slice 03). Each backend is a drop-in adapter file (`lib/providers/codex.sh`, `lib/providers/claude.sh`) implementing one fixed contract — `available`, `active_env`, `models`, `efforts`, `display`, `argv`, `filter` — and adapters are **auto-discovered**: the provider list IS the files present (`almanac_provider_list`), so there is no central provider list to keep in sync. The seam is **deep on invocation**: the adapter's `argv` yields the full exec tokens — including the sandbox→permission mapping (claude's `--permission-mode`) and `--json`-or-not by shape — into `_ALMANAC_AGENT_ARGV`, and its `filter` yields the jq event-stream program, so **no `codex …`/`claude …` literal lives outside an adapter**. `lib/agent.sh` owns discovery, name-normalising dispatch (`almanac_provider_call <name> <verb>` — the one place that turns a provider name into a function call, so no caller ever branches on provider name), and the single central remainder: the **default-selection policy** (`almanac_provider_default` — the active-env provider if installed, else the first installed in preference order claude → codex), which unifies ralph's runtime detection (`once.sh`/`afk.sh` `detect_provider`) with the launcher's provider menu so they agree. Self-contained like `lib/ui.sh` (no dependency on `lib/core.sh`), it is its own test surface (`tests/test-providers.sh`, exercising discovery, availability, active-env, menus, the codex/claude `argv` shapes, the sandbox→permission mapping, and default-selection — all behind a fake `command -v`, no real model calls). Consumers source it **directly**: the agent run shapes in `lib/agent.sh` (which dispatch argv + filter through the seam and own only execution mechanics; consumed by `lib/worker.sh`'s worker fan-out, `lib/harden-core.sh`, and ralph's `once.sh`/`afk.sh`), `lib/loop-launcher.sh` (its provider menu / availability / list), and ralph's `once.sh`/`afk.sh` (detection / availability / display name).

The **loop-adapter seam** mirrors the provider one for loops, and lives in **`lib/loops.sh`** + **`lib/loops/<name>.sh`** — extracted from the engine (loop-engine-split slice 08). Each loop is a drop-in adapter file (`lib/loops/ralph.sh`, `lib/loops/harden.sh`, `lib/loops/converge.sh`) and adapters are **auto-discovered**: the loop list IS the files present (`almanac_loop_adapter_list`), so there is no central loop list to keep in sync. `lib/loops.sh` owns discovery and name-normalising dispatch (`almanac_loop_adapter_call <name> <verb>` — the one place a loop type becomes a function call, so no caller branches on loop type). Adapters declare **launch** as three verbs that together own a loop's full launch story: `launch` (interactive config + env-export + exec — the public entry point the launcher dispatches), `launch_usage` (the `--help` text), and `exec_argv` (build the runner exec tokens into `_ALMANAC_LOOP_ARGV` — ralph's `mode`→`once.sh`/`afk.sh` under the ralph-loop skill; harden's `almanac harden <target> --loop [--rounds N]`; converge's `almanac converge --goal …`). Adapters also declare a **resume** contract — `status_to_opts <status_file>` inverts the adapter's own status schema into the key=val pairs `new_run_argv`/`new_run_env` consume, and optional `launch_backed` (defined only by ralph) signals that hub `--resume` may safely append `--yes`. `cmd/hub.sh`'s `almanac_hub_resume_or_clone` is the only consumer; it dispatches through both verbs and no longer carries a `case "$run_type"` enumerating per-loop status fields, so adding a 4th loop costs zero hub edits. The runner path **and** the per-loop config UI both live in the adapter, not the launcher — adding a 4th loop is a single file in `lib/loops/`. Adapters also share a **control** contract — the between-round dot-file basename for `stop|steer`. Every loop today uses the same `.${name}-${kind}` convention (`.ralph-stop`/`.ralph-steer`, `.harden-stop`/`.harden-steer`, `.converge-stop`/`.converge-steer`), so the pattern lives once in `lib/loops.sh` as `almanac_loop_default_signal_file` and adapters need not declare `signal_file` at all unless their convention diverges. The public resolver `almanac_loop_signal_file` returns the adapter override if defined else the default — so adding a standard new loop costs zero signal_file code, and three identical case-statements no longer have to stay in sync across adapters. `lib/run.sh` exposes `almanac_loop_run_control_file <type> <base> <kind>` as the absolute-path variant (BASE joined with the resolved basename), so harden-core and converge-core no longer reimplement their own `_control_file` wrapper each. The **launcher** (`lib/loop-launcher.sh`) consumes launch — `almanac_loop_launch` resolves `almanac_loop_<type>_launch` via the adapter seam and calls it; the adapter's launch verb in turn execs the runner via `almanac_loop_adapter_call <type> exec_argv …` rather than a hard-coded path — and the **hub** consumes control through `almanac_loop_signal_file` (above). Self-contained like `lib/agent.sh` (no dependency on `lib/core.sh` — only printf/tr/basename/source), it is its own test surface (`tests/test-loops.sh`: discovery, dispatch rejecting an unimplemented verb, the `signal_file` control mapping, `new_run_usage`, and `exec_argv` launch composition for loops against a fake `$ALMANAC_HOME`). Adding a loop is one new file under `lib/loops/`; nothing central changes.

## Validation (`lib/almanac-core.sh`)

`almanac_validate_skill()` checks against the Agent Skills Open Standard:
- Name format (regex, length, no consecutive hyphens, matches directory)
- Description presence + length (≤220 chars to keep auto-listing compact)
- Description starts with `Use when` (a leading YAML quote is stripped first) — agents under-trigger without an explicit trigger up front; the rule is in the validator, with a negative case in `tests/test-skills.sh`
- Frontmatter size
- Optional field constraints (compatibility length)
- Line count recommendation
- `metadata.dependencies` resolved by name across the whole tree (categories are transparent to deps)

`almanac_validate_unique_names()` runs once per test pass — fails if two skills under different categories share a name.

`almanac_list_skills()` and `almanac_find_skill()` are the canonical tree walkers — every CLI/test that enumerates skills uses them. Layout assumption: `skills/<category>/<name>/SKILL.md` (depth 3 from `$ALMANAC_HOME`).

## Key Principle

Skills are shared across all providers. Everything else (hooks, commands, agents) is provider-local. Adding a skill makes it available everywhere. Provider-specific features stay isolated.
