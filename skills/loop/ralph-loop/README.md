# Ralph Loop

Autonomous implementation loop. Each iteration spawns a fresh Claude Code or Codex process that picks one task from a PRD, implements it with TDD, commits, and exits. Progress lives in git, not context.

Based on [Geoffrey Huntley's Ralph Wiggum loop](https://ghuntley.com/ralph/) and [Matt Pocock's adaptation](https://github.com/mattpocock/ralph-workshop-repo-001).

## Prerequisites

- `docs/plans/<name>/prd.md` — your PRD (create with `/prd-create`)
- `docs/plans/<name>/prompt.md` — generated by running `/ralph-loop`

## Setup

Run `/ralph-loop` inside your agent. It will:

1. List available PRDs and ask which one to use (or accept a name as argument)
2. Detect your project's feedback loops with the shared loop engine
3. Generate `docs/plans/<name>/prompt.md` with the right commands
4. Print the commands to start the loop

From the repo, prompt generation can also be run directly:

```bash
bash skills/loop/ralph-loop/scripts/prompt.sh auth-system
```

## Running

### Interactive CLI

```bash
almanac ralph
```

The launcher prompts for PRD, mode, provider, model, thinking level, AFK iteration count, and overseer behavior. It then delegates to `once.sh` or `afk.sh`.

Codex output is compact by default: raw session output goes to `docs/plans/<name>/ralph-codex-*.log`, while the terminal shows concise agent progress messages and the final assistant message. Set `RALPH_CODEX_VERBOSE=1` to stream the full Codex session.

### Single iteration (human in the loop)

```bash
bash ~/.almanac/skills/ralph-loop/scripts/once.sh auth-system
```

Use the installed provider path if you are not running from the repo:
- Codex: `~/.agents/skills/almanac/ralph-loop/scripts`
- Claude Code: `~/.claude/skills/almanac/ralph-loop/scripts`

Runs one pass. You review the result before continuing. Good for:
- First iteration (sanity check the approach)
- After an abort (diagnose and unblock)
- When you want to steer

Force a provider when needed:

```bash
almanac ralph --provider codex --effort high
RALPH_PROVIDER=codex bash ~/.almanac/skills/ralph-loop/scripts/once.sh auth-system
RALPH_PROVIDER=claude bash ~/.almanac/skills/ralph-loop/scripts/once.sh auth-system
```

### Autonomous (AFK)

```bash
bash ~/.almanac/skills/ralph-loop/scripts/afk.sh auth-system 10
```

Runs 10 iterations autonomously. Stops early when:
- All tasks complete (`COMPLETE` signal)
- A task is blocked (`ABORT` signal)

### Monitoring progress

```bash
git log --grep="RALPH(auth-system)" --oneline
```

Each `RALPH(auth-system):` commit message contains what was done and notes for the next iteration. The name prefix means multiple PRDs can run against the same repo without confusing each other's progress.

## How it works

```
afk.sh auth-system 10
  └── for each iteration:
        1. Read last 10 RALPH(auth-system): commits from git log
        2. Spawn fresh Claude Code or Codex process with docs/plans/auth-system/prompt.md
        3. Agent reads PRD, breaks into tasks, picks next unfinished one
        4. Implements with TDD, runs feedback loops
        5. Commits with RALPH(auth-system): prefix
        6. Exits → next iteration
```

No subagents, no shared memory. Each iteration is a separate OS process with fresh context. Git is the only state that carries between iterations.

## Files

```
docs/plans/
├── auth-system/
│   ├── prd.md             ← from /prd-create (the PRD)
│   ├── prompt.md          ← from /ralph-loop setup
│   ├── agent-reports.log  ← appended each iteration
│   ├── overseer.log       ← overseer ticks
│   ├── ralph-codex-*.log  ← raw Codex session logs (if using Codex)
│   └── issues/            ← optional task queue (from /issues-create-local)
│       └── 01-add-login-form.md
└── dashboard/             ← another PRD (can coexist)
    ├── prd.md
    └── prompt.md
```

## Resuming

Just run `afk.sh` again with the same name. It reads `RALPH(<name>):` commits to know what's already done.
